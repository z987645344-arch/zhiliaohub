## 当前功能

### 静态前台

- 五项导航：首页、作品展示、学习心得、智能工具、反馈中心。
- `works.html` 按程序/影视/生活展示各分类最新作品，并提供三个分类二级页；作品详情采用媒体 showcase、版本日志及按数据条件显示的下载/体验按钮。
- `notes.html` 与三个详情页当前仍是占位内容。
- `tools.html` 只是智能工具规划说明，没有真实登录、注册、API 或知天工具集成。
- `feedback.html` 展示发布时查询出的 approved 顶层留言和二层回复；页面加载不实时读后台，只有主动提交留言/回复时调用公开 API。
- 小作坊项目仅在管理员开启显示后出现在作品页；ZIP内容作为独立静态站点访问。

### 管理后台

- 唯一管理员通过密码+bcrypt 哈希和 TOTP 登录；session 持久化在 SQLite。
- 配套 App 使用一次性配对码、Android Keystore P-256 私钥、短期挑战和 `SHA256withECDSA` 完成第二登录入口；服务端只保存公钥。
- 管理写操作要求已认证会话和 CSRF；认证与公开提交接口按 IP 限流。
- 作品/日记的结构化元数据存 SQLite，正文存 Markdown；保存后串行全量发布静态 HTML。
- 独立作品表单支持封面裁剪、主媒体、辅媒体、ZIP下载、体验链接和版本日志；发布时复制引用媒体并清理失效前台副本。
- 反馈公开提交统一进入 pending；后台按主题审核、拒绝、隐藏和站长回复，管理员主动全量发布后前台才更新。
- 小作坊支持管理员上传网页 ZIP、显隐和删除；写出前校验路径穿越、条目数、解压体积、扩展名、符号链接和加密条目。

### 数据与备份

- SQLite 保存内容元数据、发布状态、TOTP、session、设备认证、反馈审核队列和小作坊项目元数据。
- Markdown、普通上传、备份归档、小作坊解压内容和公开站点目录分别持久化。
- 备份覆盖 SQLite 一致性快照、作品/日记 Markdown 和上传池内非ZIP文件，包含 manifest、SHA-256、可选 AES-256-GCM 加密和保留策略；上传ZIP不入归档，只在 `manifest.excluded` 留存路径、大小和SHA-256，恢复后由用户从本地按原名补齐并校验。**一份“静默地少了东西”的备份比没有备份更危险。**
- 恢复前会自动创建可用作回退点的快照；恢复必须停服并显式使用 `--force`。
- 进程内定时备份已实现；`BACKUP_MIRROR_DIR` 仍只是同机目录副本模拟，不是真正异地容灾。
- `lab-storage/` 尚未纳入现有备份归档。

### 生产部署

- 仓库根目录 `docker-compose.yml` 定义 `admin-server` 与官方 Nginx 服务。
- 根目录 `.env` 只存 Compose 拓扑；`admin-server/.env` 保存后台密钥与业务参数，两者均不入 Git。
- 后台只在 Compose 内部网络暴露 3001；Nginx 直接伺服独立公开站点目录，并反代 `/admin`、`/api`、`/uploads`、`/health`。
- Compose 强制 `NODE_ENV=production`、`HOST=0.0.0.0`、`PORT=3001`、`TRUST_PROXY_HOPS=1` 和容器路径。
- **真实客户端 IP 还原（源站位于 Cloudflare 之后）**：`deploy/nginx.conf` 在 http 级（第一个 `server` 块之前）配置 22 条 Cloudflare 官方网段的 `set_real_ip_from` 加 `real_ip_header CF-Connecting-IP`，使 `$remote_addr` 与转发出去的 XFF 末位都成为真实访客 IP，Express 的 `req.ip` 因而正确。**`TRUST_PROXY_HOPS` 保持 1，不得改成 2**——改层数等于盲信 XFF，直连源站伪造该头即可绕过限流。网段必须限定而不能写 `0.0.0.0/0`：源站可被直连，无条件信任该头等于允许任意伪造。**这份网段列表需人工维护**，来源是 `https://www.cloudflare.com/ips-v4` 与 `ips-v6`（当前列表取于 2026-08-17）；过期的失败模式是新网段退回记 CF 边缘 IP，属优雅降级、不中断服务。
- 线上域名和 HTTPS 已真实可用。真实服务器路径、IP、证书和密钥只存在于服务器现场文件，不写入仓库文档。
- 小作坊独立子域名的真实 Cookie 隔离仍需单独确认；不能仅凭 localhost 路由或 Nginx 模板宣称已验证。

## 关键架构决定

| 决定 | 原因与边界 |
|---|---|
| 访客读取静态 HTML | 内容在发布时生成，页面加载不依赖后台内容 API；反馈提交是唯一公开写入例外 |
| 前台与后台技术栈分离 | 前台保持零构建，后台依赖与数据全部位于 `admin-server/` |
| SQLite 元数据 + Markdown 正文 | 兼顾结构化查询和正文可读性；文件与数据库只保证单进程内协调，不宣称多实例并发 |
| 保存即全量发布 | 不设草稿；发布有生成标记、受控清理和失败恢复 |
| 反馈先审后发、最多两层 | pending/rejected 不进入发布查询；邮箱和 IP 永不进入前台 HTML |
| 密码+TOTP与设备登录并行 | 设备会话不替代高权限密码+TOTP，也不能生成配对码扩大权限 |
| 作品下载为公开静态资源 | 每条作品独立开关；当前没有额外登录或授权限制 |
| 主站与 App 独立版本 | 两仓库独立提交和标签，通过 `admin-server/README.md` 维护最低兼容关系 |
| 单后台实例 | SQLite、文件发布和 session 没有多实例协调机制，不能直接水平扩容 |
| Docker/Nginx 生产部署 | 静态站、后台进程、持久目录和 TLS 边界清晰；代码或依赖更新后必须显式重建镜像 |
| Claude Code 指挥、按任务选择执行 agent | 指挥师负责现状核对、范围讨论、agent 选型、指令拆解、证据验收和文档维护；Codex 优先承担设计取向任务，Claude Code 执行者优先承担严格实现、部署和 Git/GitHub 任务，但不固定分配 |

- **Nginx `real_ip` 已实证生效**：容器内渲染后的配置含 22 条 `set_real_ip_from` 与 `real_ip_header CF-Connecting-IP`，`nginx -t` 通过；从开发机经 Cloudflare 请求唯一路径后，服务器访问日志行首记录与开发机真实出口 IP **完全一致**（改动前此处为 Cloudflare 边缘地址）。五个入口全部 200，六容器 healthy。
- ⚠️ **部署时踩到的坑，改此类配置必读**：`docker compose up -d` **不会重建 nginx 容器**——Compose 只在服务定义变化时重建，而 nginx 配置是绑定挂载的模板，源文件内容改变不触发重建。当时 `nginx -t` 通过、五个入口全部 200、容器 healthy，**但容器内渲染后的配置里 `set_real_ip_from` 是 0 条**，改动完全没生效。必须 `--force-recreate` 并**核对容器内的渲染结果**；上述三项绿灯都不能作为配置已生效的证据。
- 配套 App v0.3 已完成两个 flavor 构建、测试、Lint 和同机并装；生产与测试包的数据、Keystore 和 session 按包名隔离。

## 与知天的域名与融合边界

2026-08-16 确定的拓扑：**共用唯一顶层域名，按子域名分流到同机的两个公网 IP。**

| 域名 | 归属 |
|---|---|
| 根域与 `www` | 知了hub（首页） |
| `lab` | 小作坊 |
| `agent` | **知天**（解析到知天专属 IP） |
| `mail` | 阿里云 DirectMail |

DNS 权威在 Cloudflare（免费版），根域、`www`、`lab` 均已开启橙云代理，源站 IP 对外隐藏。**阿里云 DNS 控制台内的记录已失效**（NS 已切走，控制台顶部有明确提示），改 DNS 只认 Cloudflare。

融合分四层，成本递增，当前只做前两层：

| 层级 | 内容 | 是否需要动架构 |
|---|---|---|
| 1 跳转 | `tools.html` 放链接指向知天 | 否 |
| 2 视觉统一 | 共享导航与配色语言 | 否，各自实现 |
| 3 **登录状态共享** | 本站登录后进知天免登 | **是**，两套账号体系（本站单管理员+TOTP / 知天四角色 JWT）需 SSO 或跨子域 Cookie |
| 4 数据互通 | 本站展示知天内容 | 是，需定义 API 契约 |

> ⚠️ **第 3 层与小作坊直接冲突，必须先解决**：跨子域共享登录需要把 Cookie 设为 `domain=.zhiliaohub.com`，而 `lab` 子域承载的是**管理员上传的任意网页 ZIP**——其中任意 HTML/JS 将能读到主站与知天的认证 Cookie，等同 XSS 级越权。原本列在待办中的「小作坊子域名真实 Cookie 隔离验证」因此从"待确认"升级为**登录融合的前置必须项**。
> 另注：Cloudflare 免费通配证书只覆盖**一级**子域名，`a.b.zhiliaohub.com` 不在覆盖范围，新增子域名不要套多层。

## 不可混淆的边界

- `v2.1` 是当前功能代码基线且**已部署上线**；`v2.0.1` / `v2.0.2` 只整理文档与协作流程。注意 `v2.0` 曾在存档后三天未部署，**存档完成从来不等于线上生效**。
- 线上已部署不等于远程备份、告警、恢复演练和小作坊子域隔离全部完成。
- `real_ip` 已于 2026-08-17 随 `v2.1` 上线并用日志实证；但**「仓库里写了配置」与「线上已生效」始终是两件事**，本次正是靠核对容器内渲染结果才发现 `docker compose up -d` 没有重建 nginx。今后改此类挂载模板，必须 `--force-recreate` 并核对容器内实际渲染，不得以 `nginx -t` 通过或站点可访问作为证据。
- `docker compose up -d` 不保证使用最新代码；代码或依赖改变后必须先显式构建镜像。
- 真实 `.env`、SQLite、上传、备份、`lab-storage`、服务器路径和凭据不得进入 Git。
- 自动生成的作品、日记、分类和反馈 HTML 不应手工编辑，应通过后台数据或模板重新发布。
- `zhiliaohub_app` 是独立仓库；未明确授权时不得跨仓库修改。
