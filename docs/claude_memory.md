v2.0 完成两项本地代码与文档工作：

1. `/health` 的 `deployment` 字段不再永久硬编码为 `local-only`，而是依据现有 `NODE_ENV`：生产环境返回 `production`，开发/测试继续返回 `local-only`。

生产 Compose 已强制设置 `NODE_ENV=production`，无需新增环境变量；但Git推送不会自动更新线上容器。在用户于服务器显式拉取、重建和重启前，线上 `/health` 仍会返回旧的 `local-only`。v2.0 存档过程不自行连接或操作生产服务器。

## 当前功能

### 静态前台

- 五项导航：首页、作品展示、学习心得、智能工具、反馈中心。
- `works.html` 按程序/影视/生活展示各分类最新作品，并提供三个分类二级页；作品详情采用媒体 showcase、版本日志及按数据条件显示的下载/体验按钮。
- `notes.html` 与三个详情页当前仍是占位内容。
- `tools.html` 只是智能工具规划说明，没有真实登录、注册、API 或知天工具集成。
- `feedback.html` 展示发布时查询出的 approved 顶层留言和二层回复；页面加载不实时读后台，只有主动提交留言/回复时调用公开 API。
- 小作坊项目仅在管理员开启显示后出现在作品页；ZIP内容作为独立静态站点访问。

### 管理后台

- 唯一管理员通过密码+bcrypt 哈希和 TOTP 登录；session 持久化在 SQLite。
- 配套 App 使用一次性配对码、Android Keystore P-256 私钥、短期挑战和 `SHA256withECDSA` 完成第二登录入口；服务端只保存公钥。
- 管理写操作要求已认证会话和 CSRF；认证与公开提交接口按 IP 限流。
- 作品/日记的结构化元数据存 SQLite，正文存 Markdown；保存后串行全量发布静态 HTML。
- 独立作品表单支持封面裁剪、主媒体、辅媒体、ZIP下载、体验链接和版本日志；发布时复制引用媒体并清理失效前台副本。
- 反馈公开提交统一进入 pending；后台按主题审核、拒绝、隐藏和站长回复，管理员主动全量发布后前台才更新。
- 小作坊支持管理员上传网页 ZIP、显隐和删除；写出前校验路径穿越、条目数、解压体积、扩展名、符号链接和加密条目。

### 数据与备份

- SQLite 保存内容元数据、发布状态、TOTP、session、设备认证、反馈审核队列和小作坊项目元数据。
- Markdown、普通上传、备份归档、小作坊解压内容和公开站点目录分别持久化。
- 备份覆盖 SQLite 一致性快照、作品/日记 Markdown 和普通上传，包含 manifest、SHA-256、可选 AES-256-GCM 加密和保留策略。
- 恢复前会自动创建可用作回退点的快照；恢复必须停服并显式使用 `--force`。
- 进程内定时备份已实现；`BACKUP_MIRROR_DIR` 仍只是同机目录副本模拟，不是真正异地容灾。
- `lab-storage/` 尚未纳入现有备份归档。

### 生产部署

- 仓库根目录 `docker-compose.yml` 定义 `admin-server` 与官方 Nginx 服务。
- 根目录 `.env` 只存 Compose 拓扑；`admin-server/.env` 保存后台密钥与业务参数，两者均不入 Git。
- 后台只在 Compose 内部网络暴露 3001；Nginx 直接伺服独立公开站点目录，并反代 `/admin`、`/api`、`/uploads`、`/health`。
- Compose 强制 `NODE_ENV=production`、`HOST=0.0.0.0`、`PORT=3001`、`TRUST_PROXY_HOPS=1` 和容器路径。
- 线上域名和 HTTPS 已真实可用。真实服务器路径、IP、证书和密钥只存在于服务器现场文件，不写入仓库文档。
- 小作坊独立子域名的真实 Cookie 隔离仍需单独确认；不能仅凭 localhost 路由或 Nginx 模板宣称已验证。

## 关键架构决定

| 决定 | 原因与边界 |
|---|---|
| 访客读取静态 HTML | 内容在发布时生成，页面加载不依赖后台内容 API；反馈提交是唯一公开写入例外 |
| 前台与后台技术栈分离 | 前台保持零构建，后台依赖与数据全部位于 `admin-server/` |
| SQLite 元数据 + Markdown 正文 | 兼顾结构化查询和正文可读性；文件与数据库只保证单进程内协调，不宣称多实例并发 |
| 保存即全量发布 | 不设草稿；发布有生成标记、受控清理和失败恢复 |
| 反馈先审后发、最多两层 | pending/rejected 不进入发布查询；邮箱和 IP 永不进入前台 HTML |
| 密码+TOTP与设备登录并行 | 设备会话不替代高权限密码+TOTP，也不能生成配对码扩大权限 |
| 作品下载为公开静态资源 | 每条作品独立开关；当前没有额外登录或授权限制 |
| 主站与 App 独立版本 | 两仓库独立提交和标签，通过 `admin-server/README.md` 维护最低兼容关系 |
| 单后台实例 | SQLite、文件发布和 session 没有多实例协调机制，不能直接水平扩容 |
| Docker/Nginx 生产部署 | 静态站、后台进程、持久目录和 TLS 边界清晰；代码或依赖更新后必须显式重建镜像 |

6. 评估主仓库 CI 是否安装后台依赖并执行 `npm test`。

## 不可混淆的边界

- `v2.0` 是当前已存档主站版本；它不代表尚未执行的生产镜像更新已经完成。
- 线上已部署不等于远程备份、告警、恢复演练和小作坊子域隔离全部完成。
- `docker compose up -d` 不保证使用最新代码；代码或依赖改变后必须先显式构建镜像。
- 真实 `.env`、SQLite、上传、备份、`lab-storage`、服务器路径和凭据不得进入 Git。
- 自动生成的作品、日记、分类和反馈 HTML 不应手工编辑，应通过后台数据或模板重新发布。
- `zhiliaohub_app` 是独立仓库；未明确授权时不得跨仓库修改。
