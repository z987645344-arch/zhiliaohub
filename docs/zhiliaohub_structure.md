# 知了hub（zhiliaohub）技术架构
> 记录当前已经存在的技术结构、文件职责和明确边界；未来方案只放在“预留演进”章节，不视为已实现。
> **最后更新：2026-08-03**（v1.0 存档与轻量CI）

---

## 一、项目定位与架构原则

知了hub 是个人多作品展示网站，用于呈现作品、学习心得和后续交流入口。当前架构追求可直接阅读、可直接预览和低维护成本：

1. 使用多个独立 HTML 页面，不采用单页应用路由。
2. 全站共用 CSS 和 JavaScript，避免每页各自形成一套视觉或交互实现。
3. 不引入构建工具、包管理器、前端框架或第三方动画库。
4. 不包含后端、数据库、用户系统或真实表单提交能力。
5. 没有真实服务支撑的功能必须明确标注未开放。
6. 使用轻量CI检查确定性的语法与本地引用错误，不把浏览器回归伪装成自动化能力。

## 三、当前技术栈

| 层面 | 当前方案 |
|------|----------|
| 页面 | HTML5，多个独立页面 |
| 样式 | 原生 CSS，自定义属性、Grid、Flexbox、响应式媒体查询 |
| 交互 | 原生 JavaScript 与浏览器 DOM API |
| 首页动画 | 原生 Canvas 2D API 绘制雨滴与雾气 |
| 依赖 | 零第三方运行时依赖 |
| 构建 | 无构建步骤，无生成产物 |
| CI | GitHub Actions；对 `main` 的 push / pull request 执行静态检查 |
| 后端 | 无 |
| 数据库 | 无 |
| 内容存储 | 当前直接写在各 HTML 文件中 |
| 预览方式 | 直接打开 HTML，或使用任意本地静态文件服务器 |

所有站内资源使用相对路径，因此不依赖固定域名或服务器根路径。

## 四、页面结构与职责

| 页面 | 定位 | 当前内容 | 当前不包含 |
|------|------|----------|------------|
| `index.html` | 站点首页与视觉入口 | 站点名称、标语、作品/心得入口、OC 都市雨巷插画、Canvas 雨雾开屏 | 登录、动态数据、远程内容 |
| `works.html` | 多作品展示索引 | 8类真实作品条目、CSS分类封面和栏目插画 | 作品文件下载、动态数据、知天业务代码或真实域名 |
| 8个 `works-*.html` | 作品详情模板 | 标题、分类、状态、工作日志占位、返回入口及未开放按钮 | 真实日志、登录、下载、权限控制或远程内容 |
| `notes.html` | 学习心得索引 | 3条明确标注为占位的日期、标题、摘要及栏目插画 | 真实已发布文章、搜索或分类逻辑 |
| 3个 `notes-*.html` | 日记详情模板 | 占位标题、日期、正文筹备说明、返回与编辑入口 | 真实正文、登录、在线编辑或内容保存 |
| `feedback.html` | 未来反馈与评论入口的静态界面 | 姓名、邮箱、留言字段、评论输入、占位评论和缩进跟评；明确未开放提示 | 网络提交、存储、公开展示、邮件发送或成功回执 |

每个页面都包含共享风格的顶部导航和页脚，并通过 `aria-current="page"` 标记当前页面。由于当前没有模板或构建过程，导航 HTML 会在各页面重复；任何导航结构变更都必须同步更新全部页面。

## 五、共享资源组织

### 5.1 `css/style.css`

单一全站样式入口，当前负责：

- 水泥灰、雾蓝灰、低饱和橄榄灰等颜色变量，以及字体、间距和圆角。
- 顶部导航、品牌标记、按钮与页脚等共享组件。
- 首页开屏、作品分类卡片、作品/日记详情、日记列表、反馈表单与评论层级等页面级布局。
- 桌面端与窄屏断点，以及 `prefers-reduced-motion` 规则。

当前规模下保持一个共享样式文件最容易维护。只有当文件明显难以定位、页面数量和组件数量持续增长时，才讨论拆分；不能为了形式完整提前制造多个空样式文件。

### 5.2 `js/site.js`

所有页面都会加载的共享脚本，当前负责：

- 移动端导航的展开、关闭、Esc 键和点击外部关闭。
- 页脚当前年份填充。
- 反馈表单与评论表单的 `preventDefault()` 及未开放提示。
- 下载、登录、编辑、回复和知天展示入口等通用未开放按钮的本地状态提示。

脚本对每项功能都先检查目标元素是否存在，因此在不包含该组件的页面上不会报错。

### 5.3 `js/particles.js`

仅首页加载，负责 Canvas 雨线与雾团的创建、移动和绘制。当前性能约束包括：

- 雨滴数量按画布面积计算，并分别设置移动端和桌面端上限；雾团保持少量缓慢移动。
- 设备像素比最高按 2 处理，避免高分屏绘制成本无限增加。
- 绘制频率控制在约 45 FPS。
- 首页离开视口、浏览器页面隐藏或用户偏好减少动态效果时停止持续动画，同时保留一帧静态雨雾。
- Canvas 随首页区域尺寸变化重新适配。

该动画是装饰层，不参与页面内容表达，Canvas 对辅助技术隐藏。

### 5.4 `assets/`

当前保存首页及三个内容栏目的压缩 WebP 插画：`hero-oc-rain-alley.webp`、`works-oc-creative-passage.webp`、`notes-oc-rain-writing.webp`、`feedback-oc-message-slot.webp` 均为网站实际加载的本地静态资源；`reference/oc-three-view.jpg` 只作为开发阶段角色设定参考，并由 `.gitignore` 排除，不进入版本库。新增资产应使用能说明用途的文件名，并在入库前控制尺寸和体积。

### 5.5 `.github/workflows/ci.yml`

轻量CI仅执行两类确定性检查：

- 对仓库内全部 `.js` 文件逐个运行 `node --check`。
- 扫描全部 HTML 的 `href` 与 `src`，忽略片段和外部协议，确认本地相对引用目标存在。

工作流只在面向 `main` 的 push 和 pull request 上触发，不启动浏览器，也不执行视觉回归、性能测试、部署或后端检查。

## 六、页面加载与交互流程

```text
浏览器打开某个 HTML
   ├── 加载 css/style.css
   ├── 解析当前页面语义内容与共享导航
   └── defer 加载 js/site.js
          ├── 有导航按钮 → 绑定移动端菜单
          ├── 有反馈或评论表单 → 阻止提交并显示未开放说明
          └── 有未开放操作按钮 → 显示对应登录、下载、编辑、回复或展示入口说明

index.html 额外 defer 加载 js/particles.js
   └── Canvas 尺寸初始化 → 绘制雨滴/雾气 → 按动态效果偏好和可见性控制动画循环
```

当前所有交互均发生在浏览器本地，不发送网络请求、不持久化用户输入，也不依赖 Cookie、localStorage 或服务端会话。

## 七、可访问性、响应式与真实性约束

### 可访问性

- 每页提供“跳到主要内容”入口和有名称的主导航。
- 页面使用语义元素与清晰的标题层级。
- 移动菜单按钮暴露 `aria-expanded` 和 `aria-controls`。
- 表单字段有显式 `label`；动态状态使用可被辅助技术感知的状态区域。
- 装饰 Canvas、符号和视觉图形不承担唯一的信息传达职责。

### 响应式

- 页面主体使用受最大宽度约束的流式布局。
- 桌面导航在窄屏变为菜单按钮，主要网格在对应断点改为单列。
- 验证最低要求为常规桌面视口和约 390px 窄屏，且不得出现页面级横向滚动。

### 真实性

- `works-zhitian.html` 的展示入口是普通按钮，不包含正式地址；点击只说明知天的对外地址尚未配置。
- 所有登录、下载和日记编辑入口都是按钮，没有账号跳转、文件地址或下载属性。
- `feedback.html` 的反馈与评论表单没有 `action` 指向服务端；脚本阻止默认提交并明确说明内容不会发送、保存或公开展示。
- 占位评论、跟评和日记在可见文案中均明确标注，不伪装成真实用户内容或已发布文章。
- 在真实后端和数据链路接通且验证以前，不得把任何反馈、评论或编辑交互改成成功状态。

## 九、当前明确限制

| 限制 | 当前处理方式 |
|------|--------------|
| 没有内容管理系统 | 页面内容直接编辑 HTML |
| 没有真实文章正文 | 日记列表与3个详情页均明确标记为占位内容 |
| 没有反馈或评论后端 | 阻止提交并明确提示不发送、不保存、不公开展示 |
| 没有登录和在线编辑 | 登录、日记编辑按钮只显示未开放说明 |
| 没有下载资源与权限控制 | 下载按钮没有文件地址或下载行为 |
| 没有作品正式域名 | 知天详情页使用未开放按钮说明地址尚未配置 |
| 没有模板系统 | 导航与页脚在各 HTML 页面重复，修改时全量同步 |
| 没有自动化构建和浏览器测试 | CI只检查JavaScript语法和HTML本地引用；视觉与交互仍需按任务进行真实浏览器回归 |

这些是当前状态，不代表必须立即引入更复杂的技术方案。

## 十、预留技术演进（尚未实现）

本章只为未来讨论保留决策位置，以下内容均不是当前能力，也不授权执行者自行实施。

### 10.1 内容继续增长

如果作品、文章和详情页数量仍较少，继续使用独立 HTML 页面，并复用共享 CSS/JS。只有在重复维护已经产生真实成本时，再评估结构化内容数据或静态生成方案。届时需要明确 URL 兼容、现有页面迁移、无 JavaScript 阅读能力和构建失败回退方式。

### 10.2 引入构建工具

**预留，尚未实现。** 触发条件可以包括：页面模板重复维护频繁、需要自动压缩资源、需要从结构化内容生成大量页面，或必须加入可靠的自动化质量检查。

如果决定引入，可再规划源文件目录、公开静态资源目录、构建产物目录和开发/生产命令；具体目录名与工具选型必须在决策时确定，当前不提前创建 `src/`、`public/` 或 `dist/`。

### 10.3 引入前端框架

**预留，尚未实现。** 当前导航、卡片和表单提示都不需要框架。只有出现复杂共享状态、客户端路由或大量交互组件，并且收益明显高于依赖、构建和迁移成本时，才单独评估。引入框架不是内容增长的默认答案，也不能与“引入构建工具”混为同一个决定。

### 10.4 反馈中心接入真实后端

**预留，尚未实现。** 接入前至少需要设计和实现：

1. 独立的反馈接收 API 及其部署位置。
2. 服务端字段校验、长度限制、频率限制和反滥用策略。
3. 数据保存或通知方式、保留期限、删除方式和隐私说明。
4. 前端加载、真实成功、失败和重试状态。
5. 跨域或同源策略，以及日志中不得记录不必要的姓名、邮箱和留言原文。

只有服务端真实接收并经过端到端验证后，前端才能展示“提交成功”。后端可以是独立服务，但不应把知天 API 当作知了hub 的默认反馈后端，两项目代码边界保持不变。

### 10.5 Phase B 域名与反向代理

**预留，尚未实现。** Phase B 再根据实际服务器、证书和域名确定部署拓扑。知了hub 作为根域名主站，知天管理后台/API 使用子域名；配置归属和存放位置需要届时决定，本仓库当前不包含任何代理配置。

### 10.6 自动化验证扩展

**基础检查已实现，高阶检查尚未实现。** 当前CI只有 HTML 本地引用和 JavaScript 语法检查。如果页面数量或交互复杂度继续增加，可再讨论无障碍扫描或多视口回归；性能与视觉测试不属于 v1.0 现有能力，引入前必须先评估执行环境、稳定性和维护成本。

## 十一、架构变更规则

以下事项属于架构变化，必须先由用户与指挥师讨论，再交给执行者：

- 引入或替换前端框架、构建工具、包管理器。
- 新增后端、数据库、第三方表单或分析服务。
- 改变多页面路由方式、URL 结构或部署根路径。
- 把知天代码、部署配置或 API 直接并入本仓库。
- 将反馈内容发送到任何外部目标。

执行完成后，必须同步本文档的当前结构、`claude_memory.md` 的当前状态和 `CHANGELOG.md` 的架构决定理由。
